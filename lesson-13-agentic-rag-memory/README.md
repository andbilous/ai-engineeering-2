# Заняття 13. Agentic RAG, пам'ять і контекст

Виробник електровелосипедів «Вольт» хоче асистента підтримки. У компанії три моделі, і той самий код помилки E3 на них означає різне: на V1 City це датчик швидкості, на V2 Trek перегрів мотора, на V3 Cargo перевантаження. Тому асистент мусить пам'ятати, який велосипед у клієнта, навіть якщо той сказав про це тиждень тому. Документація лежить у `data/docs.jsonl` (20 документів), пошук по ній готовий у `kb.py`. Дані вигадані.

Агент у `agent.py` сам вирішує, чи шукати і з яким запитом, зберігає факти про клієнта через інструмент `remember`, складає контекст у межах бюджету токенів і перевіряє посилання у відповіді перед тим, як її показати.

## Встановлення

```bash
cd lesson-13-agentic-rag-memory
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                # вставте свій OPENROUTER_API_KEY
```

Без ключа працюють перевірки 1–6. Повний прогін 12 сценаріїв коштує близько $0.007.

## Що зробити

Над кожним TODO є коментар Goal / Why / Done when.

| TODO | Файл | Що |
| --- | --- | --- |
| 1 | `starter/memory.py` | `remember` і `profile`: довготривалі факти про клієнта, нове значення замінює старе |
| 2 | `starter/context.py` | `build_messages`: порядок частин контексту і бюджет токенів |
| 3 | `starter/agent.py` | `run_search`: інструмент пошуку з фільтром за моделлю велосипеда з пам'яті |
| 4 | `starter/agent.py` | `critic`: перевірка посилань у відповіді до того, як її побачить клієнт |
| 5 | `starter/memory.py` | `record_feedback`: поганий відгук з коментарем стає правилом для наступних відповідей |

## Як перевірити себе

```bash
python starter/check.py                          # перевірки 1–7: PASS, FAIL або TODO
python starter/agent.py --chat                   # розмова; /new — нова сесія, /down <коментар> — поганий відгук
python starter/agent.py --eval                   # 12 сценаріїв, результат у output/
python starter/agent.py --eval --no-memory       # кожна сесія з нуля
python starter/agent.py --eval --fixed-rag       # пошук завжди з сирим питанням, без інструмента
python starter/agent.py --eval --no-critic       # без перевірки посилань
python starter/agent.py --eval --budget 0        # уся історія в кожному запиті
```

Після TODO 1–5 мають пройти всі сім перевірок. Потім проженіть `--eval` і три варіанти без однієї частини системи. Для кожного знайдіть у `output/eval-*.json` сценарій, який зламався, і поясніть, яка частина його рятувала.

`data/` і `kb.py` змінювати не треба.
